AI Agent 通识入门

AI Agent 到底是什么？一个 12 年 Java 老兵的通识解读

雨辰 · yuchenaitech.cn

你好，我是雨辰。

在 yuchenaitech.cn 这个博客上，我主要写 AI 通识和技术原理。但说实话，最开始让我下定决心系统学 Agent 的，不是什么宏大的愿景，而是一个挺尴尬的现实——

作为一个写了 12 年 Java、带过技术团队的老兵，我发现自己对 Agent 的理解，一直停留在"更聪明的 ChatGPT"这个层面。但每次想深入聊，就发现这个理解撑不住——

"Agent 会自己调工具""Agent 有记忆""Agent 能多步规划"……这些词每个字都认识，连起来就懵了。

于是我花了时间，把小傅哥的《AI Agent 通识教程》从头啃了一遍。今天这篇，是我学完第 0 章（也是整本书的序章）后的第一手笔记，专门写给和我一样——有工程背景、但刚接触 Agent 的你。

不堆术语，咱们从一次真实的对话开始。

01先记住三句话

如果今天你只能带走三句话，就是这三句：

  1. Agent 不只是聊天——它比 ChatBot 多了一双手。
  2. Agent 会自己决定下一步做什么——你不用手把手教它调哪个 API。
  3. Agent 不是万能的——只有在"需要调工具、需要多步决策、需要持续反馈"时才值得用。

是不是有点反直觉？多数人以为 Agent 就是"更聪明的 ChatGPT"。不是的。

02看一次 Agent 干活，你就懂了

咱们问一个具体问题："北京明天适合户外运动吗？"

如果是早期的 ChatGPT，它会说："抱歉，我无法提供实时天气信息。"

但一个真正的 Agent，会这样工作：

思考　需要温度、天气、湿度数据 → 我应该调用 get_weather 工具

行动　get_weather(city="北京", date="明天")

观察　晴，28°C，湿度 45%，微风，空气良好

思考　28°C 舒适、无雨、湿度适宜 → 非常适合

回答　非常适合！建议早上 7-10 点或下午 4 点后，注意防晒

注意这个流程：感知 → 思考 → 行动 → 观察 → 回答。

整个过程不到 5 秒。但关键不在于快，而在于——它自己判断了"该调哪个工具"，自己解读了返回结果，自己给出了判断。你从头到尾没告诉它"去查天气"。

这就是 Agent 和 ChatBot 最本质的区别。

03Agent vs ChatBot：一张表看懂

对比维度 普通 ChatBot AI Agent
回答方式 基于训练数据直接回答 判断是否需要工具，主动调用
数据来源 只能用训练时的历史数据 可调 API、搜网页、查数据库
思考过程 一次生成，无中间步骤 Thought→Action→Observation 循环
纠错能力 无法自我纠错 观察后可重新决策
记忆能力 仅限当前对话 短期+长期，跨会话保持

Agent 不是"更聪明的聊天机器人"，而是一个能自主感知、思考、行动、观察的数字助手。

那怎么判断什么时候该用 Agent？一句话就够了：一步能回答的，ChatBot 够了；需要查资料、做判断、再调整的，该上 Agent 了。

04Agent 的"人体结构"：四大能力域

教程里有一个特别好的模型——把 Agent 拆成四个能力域，就像人的身体：

  • 感知（眼睛耳朵）：接收你的输入、环境信号、工具返回的结果。包括多模态输入、意图识别。
  • 思考（大脑）：推理、规划、记忆检索。这是 Agent 最核心的部分。
  • 行动（手脚）：调工具、执行代码、操作浏览器、协同其他 Agent。
  • 观察（反馈回路）：评估结果、循环决策、自我纠错。

四个能力不是孤立的，而是一个持续运转的闭环：

感知 → 思考 → 行动 → 观察 → 再思考 → ...

教程的原话很到位："Agent 的精髓不是某个单一能力的强大，而是四个能力协同运作形成的闭环。理解了闭环，就理解了 Agent。"

这个闭环到底意味着什么？打个比方——

你给一个新员工布置了一项任务："帮我确认明天北京适不适合办户外团建。"

一个只会"说话"的新人，会凭记忆回答："北京一般夏天挺热的吧，可能不太合适。"——这就是 ChatBot，只能基于已有信息猜。

但一个靠谱的新员工会怎么做？他先听清你的需求（感知），然后判断需要查天气数据（思考），接着打开天气App查北京明天的预报（行动），看到28°C晴天湿度45%之后，再综合判断（观察），最后告诉你"适合，建议早上或傍晚"（回答）。如果查完发现明天下暴雨，他会自动调整结论——"不建议户外，要不要改室内？"

这个"听需求→判断该查什么→动手去查→看结果再决定"的循环，就是 Agent 的闭环。你不需要告诉他"去查天气"，他自己会判断该做什么、做到什么程度。

如果你是程序员，这个闭环还有一个更精确的对应——这不就是咱们做业务系统时的「请求 → 处理 → 调用 → 返回 → 再决策」吗？Agent 把这整套工程思维搬到了 LLM 上。

05为什么是现在？三次进化

说到这里，可能有人会想：Agent 不就是 ChatGPT 加了个插件吗？能调天气API、能搜网页，跟装了个浏览器扩展有什么区别？

区别大了。从 ChatBot 到 Agent，不是"加插件"，是质变。要理解这个质变，得看 AI 和人的交互经历了什么：

第一代（2022-2023）纯聊天

ChatGPT 横空出世，惊艳了所有人，但它只能生成文本——不能查实时数据，不能调外部工具，不能动手。你问它天气，它说"抱歉，我无法提供实时信息"。

第二代（2023-2024）动手能力觉醒

2023 年是分水岭。6 月，OpenAI 发布 Function Calling，让 AI 第一次能主动调用外部 API；而早在 2022 年底，Google Research 和普林斯顿大学联合发表的 ReAct 论文，就已经让 AI 学会了"边想边做"——先推理该干什么，再行动，再根据结果调整。AI 从"只会说话"变成了"能动手"，但这一代仍以单步调用为主，还不能自主规划和纠错。

第三代（2024 至今）自主循环

Agent 能自己规划多步任务、循环调工具、自我纠错、持续记忆。你给它一个复杂目标，它会拆解、执行、检查、调整，直到完成。英伟达 CEO 黄仁勋说过的那句话很能代表这个阶段的本质——"Nobody writes prompts anymore. The new job is to write and handle loops."（Prompt 正在过时，Loop 才是新范式。）

"从 ChatBot 到 Agent，不是升级，是进化。" 第一代只会说话，第二代能动手，第三代会思考、会规划、会纠错——它不再是工具，而是助手。

06写在最后

如果只记住一句话，我希望是这一句：

纯 LLM 是"大脑"，Agent 是"大脑 + 手脚 + 记忆"。

Agent 比单纯的 LLM，多了四样东西：记忆系统、规划能力、工具调用、反思机制。

这也是为什么我一个 Java 程序员，敢在 12 年后重新出发学 Agent——它的底层逻辑，和我写了十几年的工程思维是通的。LLM 是引擎，Agent 是整车；而任何一个有工程思维的人——不管你写不写代码——恰好都最懂怎么造车。
